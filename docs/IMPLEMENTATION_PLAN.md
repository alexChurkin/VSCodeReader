# VSCodeReader: план реализации

Дата: 15 ноября 2026. Статус: план до начала разработки.

## Цель и первый релиз

Расширение VS Code для комфортного офлайн-чтения книг во вкладке редактора. Основной сценарий: открыть EPUB или FB2, выбрать главу, настроить оформление и продолжить с того же места после перезапуска VS Code. Исходные книги остаются неизменными; позиция и закладки хранятся отдельно.

Репозиторий на момент планирования пустой. Сначала реализуем вертикальный прототип на реальном EPUB, затем добавим FB2 через общий интерфейс форматов. Первый релиз — desktop VS Code на Windows, macOS и Linux. Поддержка vscode.dev и remote-сценариев требует отдельной проверки и не заявляется автоматически.

## Форматы и приоритеты

| Приоритет | Формат | Объём поддержки |
| --- | --- | --- |
| MVP | EPUB 2 и EPUB 3, `.epub` | Reflowable-книги: главы, оглавление NCX/nav, обложка, изображения, внутренние ссылки и сноски. Без исполнения скриптов книги. |
| MVP | FictionBook 2, `.fb2` | Метаданные, вложенные разделы, иллюстрации из binary/base64, стихотворения, сноски, UTF-8 и Windows-1251. |
| MVP | `.fb2.zip` | Безопасное чтение FB2 из ZIP; если книг несколько — выбор через Quick Pick. Обычные `.zip` не перехватываем. |
| После MVP | TXT | UTF-8, BOM и явный выбор Windows-1251; абзацы и эвристическое оглавление. |
| После MVP | HTML, HTM, Markdown | Режим книги по команде/Open With; стандартные редакторы VS Code остаются основными. |
| Отдельный этап | CBZ | Комиксы: порядок страниц, масштаб, направление чтения, позиция по странице. |
| Отдельный этап | PDF | Отдельный движок, например PDF.js, фиксированные страницы и собственные координаты позиции. Сначала оценить пользу относительно существующих расширений. |
| Исследование | MOBI, AZW3, FB3 | Оценить открытые библиотеки, лицензии и качество поддержки; не обещать до прототипа. |

DRM, AZW/KFX, DJVU, CBR, DOC/DOCX/RTF, аудиокниги, облачная синхронизация и внешние конвертеры не входят в первый релиз. Fixed-layout EPUB и мультимедийные EPUB показывают понятное сообщение об ограничении; не выдаём частичную поддержку за полную совместимость EPUB 3.

## Пользовательский интерфейс MVP

- Открытие `.epub`, `.fb2`, `.fb2.zip` из Explorer и команда `VSCodeReader: Open Book` с диалогом выбора файла.
- Вкладка Reader: оглавление, название книги, переходы между главами, прокрутка внутри главы, индикатор прогресса.
- Светлая, тёмная, sepia и тема VS Code; размер шрифта, межстрочный интервал, ширина колонки. Настройки сохраняются.
- Поиск по всей книге с результатами по главам, переходом и подсветкой совпадений; отмена долгого поиска.
- Закладки и восстановление позиции после закрытия вкладки и перезапуска VS Code.
- Клавиатурная навигация, видимый фокус, доступные подписи и масштабирование интерфейса.
- Состояния загрузки, отмены, ошибки и неподдерживаемого формата; повреждённая книга не ломает extension host.

Постраничный режим, выделения с заметками, экспорт заметок и библиотека недавних книг — после стабильного режима прокрутки. Номера страниц не используем как устойчивую позицию в reflowable-книге.

## Архитектура

### Интеграция с VS Code

TypeScript, VS Code Extension API и `CustomReadonlyEditorProvider` для книг; UI — webview с TypeScript и CSS без обязательного UI-фреймворка. Используем `workspace.fs` и URI, а не предполагаем, что любой ресурс — локальный путь. FB2 остаётся доступен как XML через Reopen Editor With.

Extension host отвечает за чтение, распаковку, парсинг, состояние и проверку сообщений. Webview получает только нужные главы и разрешённые ресурсы. Ресурсы выбранной книги материализуются в отдельный ограниченный кэш, выдаются через `asWebviewUri`; вся рабочая папка не становится доступной webview. На прототипе проверить работу относительных ссылок и CSS внутри выбранного способа изоляции.

### Общая модель книги и адаптеры

Предлагаемая структура:

```text
src/
  extension.ts
  reader/          # readonly editor, команды, жизненный цикл
  core/            # Book, Chapter, TocItem, Locator, Resource
  formats/epub/    # контейнер, OPF, spine, nav/NCX
  formats/fb2/     # XML, sections, notes, binary
  resources/       # безопасное разрешение ресурсов и кэш
  state/           # позиция, закладки, версия схемы
  search/          # извлечение текста, поиск, отмена
webview/           # UI и отображение главы
test/fixtures/     # небольшие авторские примеры и повреждённые книги
samples/           # внешний EPUB для ручной проверки и сведения об источнике
docs/              # план и решения по архитектуре
```

`BookAdapter` предоставляет `open`, `getMetadata`, `getToc`, `getChapter`, `getResource`, `dispose`. Общая модель содержит метаданные, порядок глав, дерево оглавления и ссылки на ресурсы. XHTML EPUB и FB2 преобразуются в ограниченный HTML для общего renderer. Специфичные возможности формата остаются в адаптере; добавление TXT не должно требовать изменения EPUB-парсера.

В первом техническом этапе сравнить два варианта EPUB: адаптер на ZIP/XML + общий renderer и интеграцию epub.js. epub.js — кандидат, а не уже выбранная зависимость. Решение фиксируем в ADR после проверки лицензии, состояния проекта, изоляции контента, навигации и восстановления позиции. Версии зависимостей закрепляем lock-файлом.

### Позиция, состояние и производительность

- Позиция: идентификатор главы, стабильный якорь/путь к текстовому узлу, смещение и текстовый контекст. Для EPUB оценить CFI, если выбранный движок его поддерживает. Процент — запасной способ восстановления.
- Привязка состояния к URI книги и fingerprint содержимого; изменение файла не должно незаметно переносить позицию в другой текст. Отдельно определить поведение при переносе книги и двух копиях одного файла.
- Позиция и закладки — в `globalState` с версией схемы; крупные индексы и кэш — в `globalStorageUri`. Settings API — для оформления. Синхронизацию книжных данных не включать по умолчанию.
- Debounce записи позиции, независимое состояние открытых вкладок, сохранение при скрытии/закрытии. `getState/setState` webview — для состояния UI, не единственное долговременное хранилище.
- Загружать главы и изображения по запросу, не создавать DOM всей книги. Тяжёлый парсинг/индексирование вынести из основного потока host, если замеры показывают задержки; предусмотреть отмену и освобождение памяти при закрытии.

## Обработка содержимого книг

Книга рассматривается как недоверенный документ, даже в доверенном workspace:

- Скрипты, обработчики событий, формы, iframe и активные вложения удаляются. Доступ к VS Code API есть только у кода интерфейса расширения.
- HTML/SVG и CSS проходят ограничения: убрать сетевые URL, `@import` и опасные схемы; сохранить разрешённые локальные изображения и оформление.
- CSP с nonce для скриптов расширения, узкие `localResourceRoots`, без CDN и фоновых сетевых запросов. Внешние HTTP(S)-ссылки открываются только по явному действию читателя; `command:`, `javascript:` и произвольные `file:` блокируются.
- Сообщения webview проверяются по схеме и допустимым действиям; запрос ресурсов ограничен текущей книгой.
- XML без DTD и внешних сущностей. Архивные пути проверяются после нормализации/декодирования: без абсолютных путей, `..`, symlink и выхода за кэш.
- До распаковки и во время неё применяются лимиты числа файлов, суммарного распакованного объёма и размера отдельного ресурса; учитывается фактический объём, а не только ZIP-заголовки. Стартовые бюджеты для проверки: архив 100 МиБ, распакованная книга 300 МиБ, 10 000 записей, одна глава 10 МиБ. Уточнить по корпусу книг до релиза.
- Неподдерживаемые DRM/шифрование, битые архивы и отсутствующие ресурсы дают диагностируемое сообщение. Обфускация шрифтов EPUB рассматривается отдельно от DRM; если её не реализуем, используем запасной шрифт.

## Пример EPUB и тестовый корпус

Первая реальная книга — Lewis Carroll, *Alice’s Adventures in Wonderland*, Project Gutenberg № 11:

- [Страница книги и сведения о правах](https://www.gutenberg.org/ebooks/11).
- [EPUB 3 с иллюстрациями](https://www.gutenberg.org/ebooks/11.epub3.images).
- [EPUB для старых устройств](https://www.gutenberg.org/ebooks/11.epub.images).

В `samples/README.md` фиксируем источник, дату загрузки, SHA-256 и условия использования. Файл не включаем в распространяемый VSIX. Gutenberg указывает public domain в США; сохраняем встроенные уведомления и учитываем условия Gutenberg и права в других юрисдикциях перед дальнейшим распространением.

Для воспроизводимых CI-тестов создаём маленькие собственные fixtures: EPUB 2/3 с разным порядком файлов ZIP и Unicode-путями, FB2 UTF-8/Windows-1251, вложенные разделы, сноски, картинки, FB2.ZIP с одной и несколькими книгами. Нужны также некорректный XML, отсутствующий spine/ресурс, traversal, XSS, XML entities и архивы с превышением лимитов. Большие искусственные книги генерируем скриптом; тесты не скачивают Gutenberg из сети.

## Этапы и критерии готовности

| Этап | Работа | Проверяемый результат |
| --- | --- | --- |
| 0. Основа и прототип EPUB | Каркас расширения, TypeScript, сборка, lint, fixtures, spike renderer и ADR | F5 открывает Alice во вкладке, показывает главу и изображение без сети; выбран и объяснён движок. |
| 1. EPUB reader | EPUB 2/3, spine, NCX/nav, ресурсы, безопасный renderer, оглавление и ссылки | На реальной книге и fixtures работают порядок глав, переходы и сноски; вредоносное содержимое не исполняется. |
| 2. Удобное чтение | Темы, типографика, позиция, закладки, поиск, клавиатура | После перезапуска и смены шрифта восстанавливается тот же фрагмент; поиск переходит в нужную главу. |
| 3. FB2 и FB2.ZIP | Адаптер, кодировки, notes/binary, выбор книги в архиве | EPUB и FB2 проходят одинаковые пользовательские сценарии через общий UI; XML остаётся доступен отдельно. |
| 4. Стабилизация | Лимиты, отмена, большие книги, доступность, интеграционные тесты | Нет зависания UI и неограниченной распаковки; результаты измерений и известные ограничения записаны. |
| 5. Версия 0.1.0 | README, команды, настройки, скриншоты, changelog, лицензия, сборка VSIX | Чистая установка VSIX на desktop открывает оба формата; пакет не содержит samples, тесты и кэш. Публикация — отдельное действие. |
| 6. Расширение | TXT → HTML/Markdown → постраничный режим; затем оценка CBZ/PDF | Каждый новый формат добавляется адаптером и собственными fixtures, с документированными ограничениями. |

Порядок зависимостей: 0 → 1 → 2 → 3 → 4 → 5; этап 6 — после обратной связи на MVP. Сроки оценить после spike на этапе 0, когда понятны качество renderer и сложность ресурсов.

## Проверки и критерии выпуска

- Unit-тесты: адаптеры, оглавление, кодировки, локаторы, URL ресурсов, состояние и ограничения архивов.
- Тесты UI: навигация, поиск, темы, закладки, фокус и восстановление позиции; отдельные проверки sanitization/CSP и протокола сообщений.
- Интеграционные тесты в VS Code через `@vscode/test-electron`: открытие custom editor, две книги одновременно, закрытие/повторное открытие, ошибка файла. Проверить реальный renderer в webview, не только отдельно в браузере.
- GitHub Actions: typecheck, lint, unit-тесты, сборка и VSIX; интеграционные проверки на Linux с виртуальным дисплеем, затем smoke на Windows/macOS перед выпуском.
- Начальные цели на зафиксированной машине: книга до 10 МиБ — первая глава до 2 секунд, переход к уже разобранной главе до 200 мс; параметры машины и cold/warm-замеры записать. Для книги 100 МиБ измерить память, отзывчивость и отмену. Это цели для измерения, а не обещания до прототипа.
- Установка VSIX проверяется в чистом профиле; содержимое и хэш исходной книги не меняются. Во время чтения не требуется сеть. Восстановление позиции проверяется после полного перезапуска VS Code.

## Решения перед началом реализации

1. Проверить EPUB renderer и записать ADR с выбранным подходом, зависимостями и ограничениями.
2. Определить минимальную версию VS Code по используемым стабильным API и прогнать тесты на ней и актуальном stable.
3. Выбрать лицензию проекта; составить список лицензий зависимостей и тестовых материалов.
4. Зафиксировать схему `BookAdapter` и locator на EPUB и небольшом FB2 до реализации остальных форматов.
