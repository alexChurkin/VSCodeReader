# VSCodeReader: план реализации

Дата: 15 ноября 2026. Статус: реализована версия 0.1.0: EPUB, FB2/FB2.ZIP/FBZ, TXT, CBZ, HTML/HTM, Markdown и изображения в отдельных вкладках.

## Текущий результат

- Готов этап 0: рабочая вкладка Terminal с EPUB, проверенная в VS Code 1.95.3.
- Частично выполнены этапы 1–2: spine, nav/NCX, оглавление, поиск, закладки, сохранение позиции, Unicode-переносы, Escape и ограничения архивов.
- Добавлены FB2 с вложенными разделами и изображениями base64, выбор книги в FB2.ZIP/FBZ, TXT с выбором кодировки, страницы CBZ в естественном порядке и открытие растровых иллюстраций в отдельной вкладке.
- Поддерживаются HTML/HTM и Markdown: оглавление из видимых заголовков, код, списки, таблицы и открытие локальных/base64-картинок. PDF отложен по запросу пользователя.
- Есть значок книги в Activity Bar, панель Library, прогресс и переход по позиции/проценту, именованные закладки с переименованием и удалением. Точный якорь сохраняется при resize; файловое состояние проверяется после полного перезапуска VS Code.
- Основной README на английском; рядом поддерживается README.ru.md.
- Переходы по сноскам, ленивый адаптер глав и полная проверка доступности остаются в следующих этапах.
- Решения прототипа и его ограничения описаны в [ADR 001](ADR-001-terminal-reader.md).

## Цель и первый релиз

Расширение VS Code для офлайн-чтения книг с внешним видом консольного вывода во вкладке Terminal. Это основной интерфейс MVP: моноширинный текст, оформление терминала VS Code, минимум заметных элементов читалки. Основной сценарий: открыть EPUB или FB2, выбрать главу, настроить оформление и продолжить с того же места после перезапуска VS Code. Исходные книги остаются неизменными; позиция и закладки хранятся отдельно.

Разработка ориентирована на desktop VS Code на Windows, macOS и Linux. Поддержка vscode.dev и remote-сценариев требует отдельной проверки и не заявляется автоматически.

## Форматы и приоритеты

| Приоритет | Формат | Объём поддержки |
| --- | --- | --- |
| MVP | EPUB 2 и EPUB 3, `.epub` | Reflowable-книги: главы, оглавление NCX/nav, внутренние ссылки и сноски; обложка и изображения извлекаются, но в терминале представлены текстовыми маркерами. Без исполнения скриптов книги. |
| MVP | FictionBook 2, `.fb2` | Метаданные, вложенные разделы, текстовые маркеры иллюстраций из binary/base64, стихотворения, сноски, UTF-8 и Windows-1251. |
| MVP | `.fb2.zip` | Безопасное чтение FB2 из ZIP; если книг несколько — выбор через Quick Pick. Обычные `.zip` не перехватываем. |
| После MVP | TXT | UTF-8, BOM и явный выбор Windows-1251; абзацы и эвристическое оглавление. |
| После MVP | HTML, HTM, Markdown | Режим книги по команде/Open With; стандартные редакторы VS Code остаются основными. |
| Отдельный этап | CBZ | Комиксы: порядок страниц, масштаб, направление чтения, позиция по странице. |
| Отдельный этап | PDF | Отдельный движок, например PDF.js, фиксированные страницы и собственные координаты позиции. Сначала оценить пользу относительно существующих расширений. |
| Исследование | MOBI, AZW3, FB3 | Оценить открытые библиотеки, лицензии и качество поддержки; не обещать до прототипа. |

DRM, AZW/KFX, DJVU, CBR, DOC/DOCX/RTF, аудиокниги, облачная синхронизация и внешние конвертеры не входят в первый релиз. Fixed-layout EPUB и мультимедийные EPUB показывают понятное сообщение об ограничении; не выдаём частичную поддержку за полную совместимость EPUB 3.

## Пользовательский интерфейс MVP

- Команда `VSCodeReader: Open Book` и действие в контекстном меню Explorer открывают книгу в отдельном настоящем терминале в нижней панели VS Code рядом с обычными shell-сессиями.
- Название терминала по умолчанию — название книги; имя вкладки настраивается шаблонами `{title}` и `{filename}`. Внизу — контекстная тусклая строка подсказок; обложка и прогресс в области текста не показываются постоянно.
- Оформление напоминает вывод консольной утилиты: моноширинные строки, небольшие отступы и сдержанные маркеры вроде `[text]`. По умолчанию без искусственных временных меток и случайного мусора, ухудшающих чтение; префиксы строк можно отключить.
- Шрифт, размер и цвета наследуются от настроек терминала VS Code. Авторские CSS, декоративные заголовки и картинки в основном режиме не отображаются. Иллюстрации заменяются на `[image: описание]`, структура абзацев, стихов и сносок сохраняется.
- Управление с клавиатуры в стиле `less`: `j/k` и стрелки — строки, Space/PageDown и PageUp — экран, `n/p` — главы, `/` — поиск по книге, `b` — закладка, `g` — оглавление, `?` — краткая помощь. Оглавление и закладки выбираются через Quick Pick по запросу.
- Клавиша Escape немедленно очищает экран читалки и показывает нейтральное `ready`; команда продолжения восстанавливает фрагмент. После скрытия и повторного показа старый текст не должен всплывать из scrollback.
- Поиск, закладки и позиция сохраняются между сессиями. Восстановление позиции привязано к тексту, а не к строкам терминала: изменение ширины панели переносит строки заново.
- Управляемый экран фиксированной высоты; история чтения не накапливается в scrollback. Текст не печатается автоматически и не имитирует выполнение настоящих команд.
- Состояния загрузки, отмены и ошибки оформлены краткими консольными строками; доступна команда подробной диагностики. Проверить клавиатуру и режим доступности терминала.

Изображения открываются по клавише `i` или команде Open Image в отдельной вкладке. В терминале остаются текстовые маркеры.

Обычный визуальный режим с изображениями внутри текста, webview, темами sepia и настройкой книжной типографики переносится за пределы MVP. Первый прототип должен прежде всего выглядеть как консольная вкладка. Номера экранов не используем как устойчивую позицию в reflowable-книге.

## Архитектура

### Интеграция с VS Code

Актуальные решения версии 0.1.0 см. в ADR 001.

TypeScript и VS Code Extension API. Основной UI — `window.createTerminal({ name: book.title, pty, location: TerminalLocation.Panel })` с реализацией `Pseudoterminal`. Это настоящая вкладка Terminal, управляемая расширением. Shell-процесс не запускается. `onDidWrite` выводит экран, `handleInput` обрабатывает навигацию, `setDimensions` пересчитывает переносы и высоту экрана, `close` сохраняет состояние и освобождает ресурсы.

Текст проходит через общий renderer: логические блоки → строки с учётом ширины терминальных ячеек → видимый экран. Учитываем Unicode, combining marks, широкие символы и изменение размеров. Управляющие ANSI-последовательности создаёт только renderer. На этапе прототипа проверить alternate screen buffer, очистку при Escape, отсутствие истории в scrollback, перезапуск сессии и конфликты горячих клавиш VS Code.

Extension host отвечает за чтение, распаковку, парсинг и состояние. Используем `workspace.fs` и URI. Перехват файлов через custom editor и визуальный webview — отдельный будущий режим, не обязательная зависимость MVP. FB2 по-прежнему можно открывать как XML обычным редактором.

### Общая модель книги и адаптеры

Предлагаемая структура:

```text
src/
  extension.ts
  reader/          # команды, сессии книг, жизненный цикл
  terminal/        # Pseudoterminal, ввод, экран, переносы Unicode
  core/            # Book, Chapter, TocItem, Locator, Resource
  formats/epub/    # контейнер, OPF, spine, nav/NCX
  formats/fb2/     # XML, sections, notes, binary
  resources/       # безопасное разрешение ресурсов и кэш
  state/           # позиция, закладки, версия схемы
  search/          # извлечение текста, поиск, отмена
test/fixtures/     # небольшие авторские примеры и повреждённые книги
samples/           # внешний EPUB для ручной проверки и сведения об источнике
docs/              # план и решения по архитектуре
```

`BookAdapter` предоставляет `open`, `getMetadata`, `getToc`, `getChapter`, `getResource`, `dispose`. Общая модель содержит метаданные, порядок глав, дерево оглавления и ссылки на ресурсы. XHTML EPUB и FB2 преобразуются в структурированные текстовые блоки с якорями для общего терминального renderer. Смещения в этих блоках связывают экран с поиском, сносками и закладками. Специфичные возможности формата остаются в адаптере; добавление TXT не должно требовать изменения EPUB-парсера.

Для MVP выбрать ZIP/XML-парсер и преобразование в текстовые блоки. epub.js оценивать при добавлении визуального режима: HTML-движок не требуется для терминального вывода. Решение фиксируем в ADR после проверки лицензии, состояния проекта, изоляции контента, навигации и восстановления позиции. Версии зависимостей закрепляем lock-файлом.

### Позиция, состояние и производительность

- Позиция: идентификатор главы, стабильный якорь/путь к текстовому узлу, смещение и текстовый контекст. Для EPUB оценить CFI, если выбранный движок его поддерживает. Процент — запасной способ восстановления.
- Привязка состояния к URI книги и fingerprint содержимого; изменение файла не должно незаметно переносить позицию в другой текст. Отдельно определить поведение при переносе книги и двух копиях одного файла.
- Позиция и закладки — в `globalState` с версией схемы; крупные индексы и кэш — в `globalStorageUri`. Settings API — для оформления. Синхронизацию книжных данных не включать по умолчанию.
- Debounce записи позиции, независимое состояние терминальных сессий и сохранение при навигации/закрытии. После перезапуска VS Code создаём новую сессию по команде продолжения; восстановление UI терминала само по себе не является хранилищем позиции.
- Загружать главы по запросу, выводить только видимый экран и не распаковывать все изображения для текстового режима. Тяжёлый парсинг/индексирование вынести из основного потока host, если замеры показывают задержки; предусмотреть отмену и освобождение памяти при закрытии.

## Обработка содержимого книг

Книга рассматривается как недоверенный документ, даже в доверенном workspace. Для MVP текстовый вывод не исполняет HTML/CSS/JS. Обязательно удаляем из книжного текста ESC, C0/C1 и управляющие последовательности OSC/CSI: книга не может менять заголовок терминала, записывать clipboard, создавать терминальные ссылки или управлять экраном. Разрешённые переводы строк и табуляция нормализуются renderer. Ни текст книги, ни ввод читателя не передаются в shell.

При добавлении визуального webview применяются дополнительные ограничения:

- Скрипты, обработчики событий, формы, iframe и активные вложения удаляются. Доступ к VS Code API есть только у кода интерфейса расширения.
- HTML/SVG и CSS проходят ограничения: убрать сетевые URL, `@import` и опасные схемы; сохранить разрешённые локальные изображения и оформление.
- CSP с nonce для скриптов расширения, узкие `localResourceRoots`, без CDN и фоновых сетевых запросов. Внешние HTTP(S)-ссылки открываются только по явному действию читателя; `command:`, `javascript:` и произвольные `file:` блокируются.
- Сообщения webview проверяются по схеме и допустимым действиям; запрос ресурсов ограничен текущей книгой.

Общие ограничения парсеров и архивов применяются уже в MVP:

- XML без DTD и внешних сущностей. Архивные пути проверяются после нормализации/декодирования: без абсолютных путей, `..`, symlink и выхода за кэш.
- До распаковки и во время неё применяются лимиты числа файлов, суммарного распакованного объёма и размера отдельного ресурса; учитывается фактический объём, а не только ZIP-заголовки. Стартовые бюджеты для проверки: архив 100 МиБ, распакованная книга 300 МиБ, 10 000 записей, одна глава 10 МиБ. Уточнить по корпусу книг до релиза.
- Неподдерживаемые DRM/шифрование, битые архивы и отсутствующие ресурсы дают диагностируемое сообщение. Обфускация шрифтов EPUB рассматривается отдельно от DRM; если её не реализуем, используем запасной шрифт.

## Пример EPUB и тестовый корпус

Первая реальная книга — Lewis Carroll, *Alice’s Adventures in Wonderland*, Project Gutenberg № 11:

- [Страница книги и сведения о правах](https://www.gutenberg.org/ebooks/11).
- [EPUB 3 с иллюстрациями](https://www.gutenberg.org/ebooks/11.epub3.images).
- [EPUB для старых устройств](https://www.gutenberg.org/ebooks/11.epub.images).

В `samples/README.md` фиксируем источник, дату загрузки, SHA-256 и условия использования. Файл не включаем в распространяемый VSIX. Gutenberg указывает public domain в США; сохраняем встроенные уведомления и учитываем условия Gutenberg и права в других юрисдикциях перед дальнейшим распространением.

Для воспроизводимых CI-тестов создаём маленькие собственные fixtures: EPUB 2/3 с разным порядком файлов ZIP и Unicode-путями, FB2 UTF-8/Windows-1251, вложенные разделы, сноски, картинки, FB2.ZIP с одной и несколькими книгами. Нужны также некорректный XML, отсутствующий spine/ресурс, traversal, XSS, XML entities и архивы с превышением лимитов. Большие искусственные книги генерируем скриптом; тесты не скачивают Gutenberg из сети.

## Этапы и критерии готовности

| Этап | Работа | Проверяемый результат |
| --- | --- | --- |
| 0. Основа и прототип EPUB | Каркас расширения, TypeScript, сборка, lint, fixtures, spike терминального renderer и ADR | F5 открывает Alice в Terminal с названием книги, показывает экран текста без сети; выбран и объяснён движок. |
| 1. EPUB reader | EPUB 2/3, spine, NCX/nav, текстовые блоки, безопасный терминальный renderer, оглавление и сноски | На реальной книге и fixtures работают порядок глав, переходы и сноски; вредоносное содержимое не исполняется. |
| 2. Удобное чтение | Переносы, очистка экрана, позиция, закладки, поиск, клавиатура | После перезапуска и изменения ширины терминала восстанавливается тот же фрагмент; поиск переходит в нужную главу. |
| 3. FB2 и FB2.ZIP | Адаптер, кодировки, notes/binary, выбор книги в архиве | EPUB и FB2 проходят одинаковые пользовательские сценарии через общий UI; XML остаётся доступен отдельно. |
| 4. Стабилизация | Лимиты, отмена, большие книги, доступность, интеграционные тесты | Нет зависания UI и неограниченной распаковки; результаты измерений и известные ограничения записаны. |
| 5. Упаковка | README, команды, настройки, скриншоты, актуальная документация, лицензия, сборка VSIX | Чистая установка VSIX на desktop открывает оба формата; пакет не содержит samples, тесты и кэш. Публикация — отдельное действие. |
| 6. Расширение | TXT → HTML/Markdown → визуальный режим с изображениями; затем оценка CBZ/PDF | Каждый новый формат добавляется адаптером и собственными fixtures, с документированными ограничениями. |

Порядок зависимостей: 0 → 1 → 2 → 3 → 4 → 5; этап 6 — после обратной связи на MVP. Сроки оценить после spike на этапе 0, когда понятны качество renderer и сложность ресурсов.

## Проверки и критерии выпуска

- Unit-тесты: адаптеры, оглавление, кодировки, локаторы, URL ресурсов, состояние и ограничения архивов.
- Тесты терминального renderer: навигация, поиск, закладки, переносы Unicode, resize и восстановление позиции; инъекции ANSI/OSC/CSI не достигают терминала. Escape очищает видимый экран и scrollback; возврат к вкладке не раскрывает текст до продолжения.
- Интеграционные тесты в VS Code через `@vscode/test-electron`: создание Pseudoterminal в панели, две книги одновременно, закрытие/повторное открытие, ошибка файла. Ручная проверка в настоящем Terminal: оформление похоже на консольный вывод, нет обложек, постоянных книжных панелей и заголовка книги; resize, фокус, scrollback и горячие клавиши работают.
- GitHub Actions: typecheck, lint, unit-тесты, сборка и VSIX; интеграционные проверки на Linux с виртуальным дисплеем, затем smoke на Windows/macOS перед выпуском.
- Начальные цели на зафиксированной машине: книга до 10 МиБ — первая глава до 2 секунд, переход к уже разобранной главе до 200 мс; параметры машины и cold/warm-замеры записать. Для книги 100 МиБ измерить память, отзывчивость и отмену. Это цели для измерения, а не обещания до прототипа.
- Установка VSIX проверяется в чистом профиле; содержимое и хэш исходной книги не меняются. Во время чтения не требуется сеть. Восстановление позиции проверяется после полного перезапуска VS Code.

## Решения перед началом реализации

1. Проверить терминальный renderer и извлечение текста EPUB и записать ADR с выбранным подходом, зависимостями и ограничениями.
2. Определить минимальную версию VS Code по используемым стабильным API и прогнать тесты на ней и актуальном stable.
3. Выбрать лицензию проекта; составить список лицензий зависимостей и тестовых материалов.
4. Зафиксировать схему `BookAdapter` и locator на EPUB и небольшом FB2 до реализации остальных форматов.
