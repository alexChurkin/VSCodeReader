# ADR 001: текстовый EPUB reader в настоящем Terminal

Дата: 2026-11-15. Статус: принято для первого прототипа.

## Решение

Основной UI — `Pseudoterminal`, созданный через `window.createTerminal`, без shell-процесса. Имя по умолчанию — `output`, оформление наследуется от терминала. Вывод в alternate screen buffer ограничен видимым экраном; Escape очищает экран и scrollback, оставляя `ready`. Только явная команда продолжения возвращает текст. Оглавление, поиск и закладки открываются по запросу через Quick Pick.

EPUB распаковывается через yauzl с ленивым перечислением записей и потоковым контролем фактического объёма. Читаются только package, container, nav/NCX и XHTML из spine. Изображения не распаковываются: в тексте остаются маркеры. HTML разбирается htmlparser2, XML-метаданные предварительно проверяются fast-xml-parser. Внешние DTD не загружаются, внутренние DTD и ENTITY запрещены. Обычные объявления типа HTML/NCX считаются инертной разметкой.

Разбор всей книги выполняется в отдельном worker с лимитом JS heap 256 МиБ; отмена завершает worker. Для прототипа текст глав хранится в памяти после разбора. Это осознанное упрощение относительно будущего ленивого `BookAdapter`: общий API адаптеров и загрузка отдельных глав остаются следующим этапом. Дополнительный лимит фактически прочитанных XML/XHTML — 32 МиБ, отдельного ресурса — 10 МиБ.

Renderer переносит текст по ширине терминальных ячеек и границам grapheme clusters. Позиция — индекс главы и UTF-16 смещение в нормализованном тексте, а не номер экранной строки. При resize выбирается строка, содержащая сохранённое смещение. Данные состояния привязаны к URI и SHA-256 исходных байтов; изменённый файл начинает новую сессию.

## Причины

Пользователю нужен внешний вид обычной консольной вкладки. HTML-движок epub.js и custom editor с webview не дают преимущества для первого текстового режима. Отделение parser/screen/state от VS Code позволяет проверять большую часть поведения без Electron.

## Ограничения прототипа

- Только reflowable EPUB 2/3. FB2/FB2.ZIP ещё не реализованы.
- Ссылки оглавления с fragment работают; произвольные ссылки и интерактивные переходы по сноскам в тексте пока не реализованы.
- Текст извлекается без авторского CSS; CSS-hidden контент может присутствовать. Стихи и таблицы пока имеют упрощённое форматирование.
- Только первые 200 результатов поиска; полноценное индексирование и отмена поиска ещё не нужны при текущем лимите текста.
- Нет изображений, пагинации по книжным страницам, DRM, мультимедийного и fixed-layout renderer.
- Изменение книги сбрасывает позицию. Перенос/копирование файла не переносит состояние автоматически.
- Мобильность состояния между версиями нормализации текста потребует новой версии схемы.
- Восстановление после перезапуска — через Resume Reading; автоматическое оживление Pseudoterminal не заявляется.
- Escape работает, когда фокус в reader terminal; для остальных областей есть команда Hide Text. Очистка касается UI расширения, а не записей экрана и внешнего журналирования.

## Зависимости и упаковка

Runtime-библиотеки имеют лицензии MIT/BSD; полные тексты лицензий фактически включённых в bundle зависимостей автоматически собираются в `dist/THIRD_PARTY_NOTICES.txt`. Лицензия собственного кода пока не выбрана (`UNLICENSED`), публикация в Marketplace не выполняется. Пример Gutenberg, тесты и исходники не включаются в VSIX.

У dev-инструмента vsce временно переопределён minimatch на 11.0.1 или новее: штатная зависимость 10.x отмечена npm advisory GHSA-g3hv-75wg-m249. Совместимость проверяется реальной сборкой VSIX; override убрать после исправления upstream.
