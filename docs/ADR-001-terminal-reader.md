# ADR 001: терминальная читалка в VS Code

Дата: 2026-11-15. Статус: принято, обновлено для версии 0.1.0.

## Решение

Основной UI — `Pseudoterminal`, созданный через `window.createTerminal`, без shell-процесса. Имя вкладки по умолчанию — название книги; доступны шаблоны `{title}` и `{filename}`. Оформление наследуется от терминала. Вывод в alternate screen buffer ограничен видимым экраном; Escape очищает экран и scrollback, оставляя `ready` и подсказку. Клавиша `r` или команда продолжения возвращает текст. Оглавление, поиск и закладки открываются по запросу через Quick Pick.

EPUB распаковывается через yauzl с ленивым перечислением записей и потоковым контролем фактического объёма. Читаются только package, container, nav/NCX и XHTML из spine. В тексте остаются маркеры изображений. По клавише `i` извлекается выбранный растровый ресурс и открывается в отдельной вкладке встроенного image viewer VS Code; команда Open Image позволяет выбрать любое изображение книги. SVG не отображается, но ссылки из SVG-обёрток на растровые картинки учитываются. Удалённые изображения не загружаются. HTML разбирается htmlparser2, XML-метаданные предварительно проверяются fast-xml-parser. Внешние DTD не загружаются, внутренние DTD и ENTITY запрещены. Обычные объявления типа HTML/NCX считаются инертной разметкой.

Форматы выбираются через общий dispatcher `readBook` / `extractImage`: EPUB, FB2, FB2.ZIP/FBZ, TXT, CBZ, HTML/HTM и Markdown. В ZIP с несколькими FB2 сначала возвращается список, затем парсится выбранная запись. FB2 использует общий renderer структурированных блоков, сохраняет вложенное оглавление, стихи и примечания как разделы. TXT поддерживает BOM и явную настройку Windows-1251. CBZ строит оглавление из растровых файлов с естественной сортировкой имён; каждая страница имеет собственную позицию.

Разбор всей книги выполняется в отдельном worker с лимитом JS heap 256 МиБ; отмена завершает worker. Для прототипа текст глав хранится в памяти после разбора. Это осознанное упрощение относительно будущего ленивого `BookAdapter`: общий API адаптеров и загрузка отдельных глав остаются следующим этапом. Дополнительный лимит фактически прочитанных XML/XHTML — 32 МиБ, отдельного ресурса — 10 МиБ.

Renderer переносит текст по ширине терминальных ячеек и границам grapheme clusters. Позиция — индекс главы и UTF-16 смещение в нормализованном тексте, а не номер экранной строки. При resize выбирается строка, содержащая сохранённое смещение. Данные состояния привязаны к URI, выбранной записи FB2-архива, кодировке текстовых документов и SHA-256 исходных байтов; изменённый файл начинает новую сессию.

## Причины

Пользователю нужен внешний вид обычной консольной вкладки. HTML-движок epub.js и custom editor с webview не дают преимущества для первого текстового режима. Отделение parser/screen/state от VS Code позволяет проверять большую часть поведения без Electron.

## Ограничения прототипа

- EPUB 2/3 поддерживает reflowable-текст; FB2, FB2.ZIP/FBZ, TXT и CBZ также поддерживаются.
- Ссылки оглавления с fragment работают; произвольные ссылки и интерактивные переходы по сноскам в тексте пока не реализованы.
- EPUB/HTML учитывают ограниченное подмножество текстового CSS. EPUB/HTML/Markdown/FB2 используют общие стили, абзацные отступы и адаптивные таблицы; FB2 сохраняет строки стихов и разделение строф. Полная браузерная вёрстка не реализована.
- Только первые 200 результатов поиска; полноценное индексирование и отмена поиска ещё не нужны при текущем лимите текста.
- Изображений внутри терминала нет: PNG/JPEG/GIF/WebP/BMP открываются в отдельной вкладке. В CBZ переход страницы сам по себе не открывает картинку. Нет пагинации текстовых книг по фиксированным страницам, DRM, мультимедийного и fixed-layout renderer.
- Изменение книги сбрасывает позицию. Перенос/копирование файла не переносит состояние автоматически.
- Мобильность состояния между версиями нормализации текста потребует новой версии схемы.
- Восстановление после перезапуска — через Resume Reading; автоматическое оживление Pseudoterminal не заявляется.
- Escape работает, когда фокус в reader terminal; для остальных областей есть команда Hide Text. Очистка касается UI расширения, а не записей экрана и внешнего журналирования.

## Панель, прогресс и сохранение

Используется Activity Bar container Reader с SVG-иконкой книги и TreeDataProvider Library. Панель показывает заголовок книги, оглавление, прогресс, открытые/последние книги и закладки. Вкладка терминала показывает название книги; визуальная навигация также доступна в боковой панели.

Устойчивая текстовая позиция — примерно 1000 UTF-16 единиц на всю книгу. Номера экранов относятся к текущей главе и пересчитываются при resize. Переход возможен по позиции и проценту. Якорь хранится отдельно от начала видимой строки: resize больше не округляет его назад. PageDown/Space и PageUp переходят между главами; n/p на границах больше не сбрасывают главу в начало.

Закладки сохраняют координаты и имя. Быстрая закладка подтверждается через status bar; именование, переход, переименование и удаление доступны в панели и командах. Одна позиция не создаёт дубликатов.

Состояние хранится в атомарных JSON-файлах `globalStorageUri/reading-state-v1`, с сериализованной очередью записей и чтением старых Memento как миграционного источника. Локальные записи используют Node fs, чтобы сброс при завершении не зависел от IPC workbench. Автосохранение идёт каждые 200 мс активной навигации, а также при скрытии и закрытии. Штатный shutdown ждёт очередь. Внезапное аварийное завершение может потерять незавершённую запись; готовый файл не заменяется частичным.

Интеграционный тест запускает VS Code дважды с одним storage: первый процесс сохраняет именованную закладку и позицию, второй продолжает чтение и проверяет точное совпадение. Это учитывает то, что штатный extension test host использует in-memory Memento.

## Подсказки и завершение сессии

Последняя строка терминала зарезервирована под тусклые контекстные подсказки (SGR dim). Доступная высота текста и счётчик экранов учитывают эту строку. Подсказка выводится абсолютным позиционированием без переноса в последней ячейке; текст укорачивается по ширине терминальных ячеек и границам grapheme clusters. При resize текстовый якорь сохраняется. В однострочном терминале строка подсказок не отнимает место у текста.

Режимы подсказок: чтение, скрытый текст, поиск, выбор пункта, ввод имени/позиции и загрузка картинки. `?` показывает полную справку, `r` возвращает скрытый текст, `q` закрывает сессию. Подтверждение сохранения закладки показывается в самой нижней строке. Справа закреплён счётчик `Page N/M | percent%`: текстовые страницы соответствуют фиксированным отрезкам по 1000 символов, CBZ использует номера страниц-картинок. Счётчик приоритетнее подсказок и уведомлений и остаётся видимым также в режимах поиска, выбора и загрузки изображения; при скрытии текста он убирается.

При закрытии PTY ровно один раз отправляет onDidClose с успешным кодом, восстанавливает атрибуты/курсор и освобождает таймеры. Это подтверждает завершение процесса для действия корзины VS Code. Терминалы transient, закрытая сессия сразу убирается из Library. Незавершённое открытие картинки отменяется при закрытии, а отложенный предпросмотр не может заново открыть вкладку после закрытия reader.

## HTML и Markdown

Markdown разбирается закреплённой версией marked; полученный HTML передаётся только текстовому renderer, а не webview. HTML разбирается htmlparser2. Видимые заголовки h1–h6 создают разделы и оглавление. Для новых форматов renderer сохраняет whitespace в pre/code, маркеры списков и задач, разделители ячеек таблиц; вывод существующих EPUB/FB2 не меняется. Длинные разделы разбиваются до 64 000 UTF-16 символов.

HTML учитывает meta charset, BOM имеет приоритет; Markdown использует BOM или настройку textEncoding. Файлы по-прежнему открываются стандартными редакторами VS Code, читалка вызывается явной командой. PDF не добавляется.

Локальные иллюстрации читаются по запросу из папки документа. Пути декодируются, нормализуются и проверяются до чтения; realpath блокирует выход через symlink. Читаются только обычные файлы, поток ограничен 10 МиБ. URI file требуется только для локальных иллюстраций; встроенные data URL разбираются в worker. Сетевые URL, SVG, абсолютные пути, выход в родительскую папку, base и srcset не используются.

## Предпросмотр изображений

Содержимое извлекается в worker только по запросу. До открытия проверяются сигнатура, тип и размеры: до 10 МиБ, 40 мегапикселей и 16 384 пикселя по стороне. SVG не передаётся в viewer. Имена временных файлов генерируются из SHA-256 изображения и проверенного расширения; пути книги не используются как пути записи. В FB2 проверяется base64. Если хэш исходной книги изменился, сессию нужно переоткрыть.

Кэш в `globalStorageUri/image-cache` ограничен 128 файлами / 100 МиБ. Записи сериализованы, старые ресурсы вытесняются; исходная книга не меняется. Native image viewer открывается с `preview: false`, `ViewColumn.Beside` и `preserveFocus: true`. Клавиатурная навигация остаётся в терминале.

## Зависимости и упаковка

Runtime-библиотеки имеют лицензии MIT/BSD; полные тексты лицензий фактически включённых в bundle зависимостей автоматически собираются в `dist/THIRD_PARTY_NOTICES.txt`. Лицензия собственного кода пока не выбрана (`UNLICENSED`), публикация в Marketplace не выполняется. Пример Gutenberg, тесты и исходники не включаются в VSIX.

У dev-инструмента vsce временно переопределён minimatch на 11.0.1 или новее: штатная зависимость 10.x отмечена npm advisory GHSA-g3hv-75wg-m249. Совместимость проверяется реальной сборкой VSIX; override убрать после исправления upstream.
